# R17-r1 — Rapport d'implémentation

## Source figée

Baseline R16 : `@vevedh/vite-plugin-feathersjs@0.2.6`, certifiée Windows Edge pour Quasar SSR Koa et Express en développement et production. Les 20 fichiers du manifeste R16 ne sont pas modifiés.

## Périmètre livré

- Nouveau générateur `scripts/generate-r17-project.mjs` réutilisant le planificateur R15, à effet contrôlé : `--name`, `--dir`, `--ui`, `--render spa`, `--adapter koa|express`, `--transport rest|both`, `--dry-run` et `--json`.
- Templates autonomes SPA Quasar 2 et daisyUI, exemples générés versionnés. API Feathers `notes`/`health` basée sur l'exemple R16, Pinia, Socket.IO facultatif et serveur API distinct.
- Cas Quasar SSR : exemple R16 existant, réutilisé sans copie ni modification.
- Cas Quasar SSG : blueprint de migration vers `@quasar/app-vite` v3 et garde explicitement bloquante ; incompatible avec une revendication de certification R16 v2.
- Cas daisyUI SSR : Vue SSR avec Pinia par rendu et service Feathers indépendant. Serveur SSR candidat (développement et production) ; aucun résultat E2E Windows acquis.
- Cas daisyUI SSG : pages publiques `/` et `/about` pré-rendues, notes récupérées seulement après hydratation. Build à certifier sous Windows.

## Validation et limites

Le contrôle `node scripts/check-r16-freeze.mjs` vérifie l'immuabilité des fichiers R16. Les tests Node vérifient les refus de paramètres, de collisions, les liens symboliques et les exemples. L'installation des nouvelles dépendances et les E2E demandent Windows et ne doivent pas être considérés comme validés avant exécution.

La version npm 0.2.6 est figée ; aucun publish associé à cette candidate.
